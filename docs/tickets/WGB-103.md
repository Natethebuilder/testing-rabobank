# WGB-103 · Security and privacy review before the audit

**Type:** Task · **Priority:** High · **Component:** whole repository

## Story

> "The internal audit of Woodgrove Transfers starts next month. Before they arrive, I'd like a fresh pair of eyes on the code: what do we log, which secrets are in the repository, how do we handle user input, and what do our error responses reveal?"
>
> — Engineering lead, Payments

## Scope

- **Logs:** what ends up in log output, and does it contain personal data?
- **Secrets:** keys, tokens or passwords in the code.
- **User input:** everything a customer can type in the transfer console or send to the API.
- **Error responses:** what `server.js` returns when something goes wrong, and how it handles large or unexpected requests.

## Acceptance criteria

- [x] A list of findings, each with a severity (High, Medium, Low), the file and a short explanation.
- [x] All high-severity findings are fixed, each with a test where that's possible.
- [x] Nothing that customers or the API rely on breaks: all tests pass.

## Findings

| # | Severity | File | Finding | Status |
|---|---|---|---|---|
| 1 | High | `src/config.js` | Live screening API key hardcoded, served at `/src/config.js` and loaded in every browser. Also in git history (`0089c5d`). | Fixed: read from `SCREENING_API_KEY`. **Rotate the key and purge it from history.** |
| 2 | High | `data/accounts.js`, `server.js` | Full IBAN → holder-name directory served at `/data/accounts.js`. | Fixed: `data/` not served; `GET /accounts` (masked) and `POST /payee-check` instead. |
| 3 | High | `server.js` | 500 responses returned `err.message` and `err.stack` with file paths; `GET /ibans/%E0` crashed. | Fixed: generic `INTERNAL_ERROR`; 400 `INVALID_IBAN_PATH`. |
| 4 | Medium | `src/transfer.js`, `server.js` | No type checks on request fields (object `description` crashes), no name length limit, same-account check not normalized. | Open |
| 5 | Medium | `server.js` | No authentication; any caller can debit any `fromIban`. | Open |
| 6 | Low | `server.js` | No body size limit, no `Content-Type` check, no CSRF protection. | Open |
| 7 | Low | `console/console.js` | Result rendered with `innerHTML` (self-XSS via description). | Open |
| 8 | Low | `server.js` | No security headers (CSP, nosniff, frame-ancestors). | Open |

Logs were reviewed: they contain only masked IBANs, id, status and amount.
